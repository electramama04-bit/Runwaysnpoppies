# Runways & Poppies

A small website for sharing free homeschool materials — planning guides, lab
sheets, nature journal pages, trip cards, and the hours log — from an
aviation-themed year in Tacoma, Washington.

Built as a Cloudflare Worker with static assets.

## What's here

| Path | What it does |
|------|--------------|
| `/` | Home page — intro and featured downloads |
| `/downloads` | The full library, filterable by curriculum quarter |
| `/links` | Curated links, grouped by category |
| `/api/documents` | JSON feed of every document |
| `/api/links` | JSON feed of every link |
| `/download/<id>` | Serves a file as a proper "Save as" download |

Static pages are served straight from `public/`. The Worker handles the two API
routes and `/download/*`, which wraps the file with a `Content-Disposition`
header so browsers save it under a readable name (`Paper_Airplane_Lab.pdf`)
rather than previewing it or saving the raw filename.

## Adding a document

1. Drop the file into `public/files/` — for example `hours-log-template.xlsx`.
2. Add an entry to `DOCUMENTS` in `src/catalog.ts`. Match `file` to the filename exactly.
3. Fill in the real `sizeLabel` (e.g. `"1.2 MB"`) and `updated` date.
4. `npm run deploy`

The `id` becomes the public URL (`/download/hours-log-template`), so once you've
shared a link, don't change that id.

Adding a link is the same idea — add an entry to `LINKS` in the same file. New
categories create their own heading automatically.

**The six documents currently in `src/catalog.ts` are placeholders.** They are
shaped from the real curriculum so the pages render and filter correctly, but the
files themselves aren't in `public/files/` yet. Until a file is uploaded, its
Download button returns a clear message rather than a broken page.

## Commands

```bash
npm run dev      # local server at http://127.0.0.1:8787
npm run check    # regenerate types, typecheck, and dry-run the deploy
npm run deploy   # publish to Cloudflare
```

Before the first deploy you'll need to authenticate: `npx wrangler login`.

## Notes on the setup

- `compatibility_date` is set to the scaffold date (2026-09-09). Review the
  [compatibility changelog](https://developers.cloudflare.com/workers/configuration/compatibility-dates/)
  before advancing it.
- `worker-configuration.d.ts` is generated by `wrangler types` from
  `wrangler.jsonc` — it is committed so a fresh clone type-checks immediately.
  Re-run `npm run types` after changing any binding.
- Workers Logs and Traces are enabled in `wrangler.jsonc`. Logs are written as
  structured JSON so they're searchable in the dashboard.
- There are no secrets and no database. Everything is static files plus one
  small Worker.
